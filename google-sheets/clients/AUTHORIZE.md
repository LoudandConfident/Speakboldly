# Client authorization and private student access

## Apps Script email actions

Replace the existing standalone Clients Code.gs with the complete script provided as Complete-Code.gs, or use StandaloneClients.gs, Sessions.gs, TeacherDocuments.gs and EmailActions.gs together. Do not install both variants. Keep the existing CLIENT_SHEET_ID, CLIENT_SYNC_KEY and reminder trigger. Save and update the existing web-app deployment to a New version. Its /exec URL stays unchanged.

Authorize beside a client opens individual confirmation email, Progress Report, final Report, Payment and registration confirmation, and exam selection. Report actions open the editable PDF for that client. Review the fields, choose Send to client, then Send email. The completed PDF is attached; a document is not emailed simply by opening it. Recipients are read from Clients server-side. EmailLog records acceptance and uncertain deliveries; uncertain sends are not automatically repeated. Google acceptance is not proof of inbox delivery. Send a test to an owner-controlled client address first.

## Exam grants

The exam chooser stores section:exams and the selected exam file grant in the client's Permissions column. Other folder grants remain. This selection replaces previously granted exam files for that client. Teacher devices share it via the Clients sheet. The existing four-digit client passcode remains unchanged.

## Private student server deployment required

The public site's exam-config.js currently has an empty EXAM_BACKEND_URL. Student login therefore remains a local-browser prototype until a private server is hosted and connected. Do not claim client devices can use sheet permissions before this is done.

The repository includes render.yaml for the prepared Node 24 service. Deploy it in the owner's hosting account with persistent storage; the existing Render starter plan is paid. Supply EXAM_CLIENT_SHEET_KEY privately in the hosting environment, never in GitHub or chat. EXAM_CLIENT_SHEET_URL is the existing /exec URL. EXAM_ADMIN_PASSWORD is generated by the blueprint. SMTP is not required for the sheet-based report emails. Existing backend score emails need SMTP if enabled separately.

After hosting succeeds, set EXAM_BACKEND_URL in exam-config.js to its exact returned HTTPS URL and publish the site. The private server reads Clients on student login and refreshes permissions at most every 30 seconds. Sheet outages fail closed; missing sheet clients are disabled. Passwords and sheet keys stay server-side. The server enforces selected exam access and handles private submissions/reviews. Test the selected exam with a client code from an unrelated device and verify another exam is denied before inviting clients.
